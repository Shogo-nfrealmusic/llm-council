== BRIEF ==
A subscription app currently costs $9 per month. The decision is whether to raise it to $19 per month, a 111% increase, starting next week. The options are: raise to $19 on that schedule, keep $9, or make a different change, such as another price, a later date, or applying it only to some users. Unknown: number of subscribers, monthly churn, revenue, costs, competitor pricing, the app's category, whether current subscribers keep the old price, whether anyone has tested if users will pay $19, and whether the product changes along with the price.
Removed framing: "I'm sure users will pay", "Good idea?"

Convergence: all 3 reviewers called it suspect (a textbook grandfather-and-test answer).

== CHAIRMAN ==
VERDICT: CHANGE IT — Charge $19 to new signups next week; existing users stay at $9 for now.

DECIDED BY: Losses can't be undone evenly. A $19 price for new signups can be reverted
the next day. An existing user who cancels after a sudden 111% jump rarely comes back.
Contrarian showed how that failure unfolds. Executor made the reversibility argument.

STRONGEST OBJECTION STILL STANDING: New-signup data only shows whether new users will pay
$19, not whether existing ones will. If $9 loses money, grandfathering just delays
insolvency.

WHERE THE COUNCIL DISAGREED:
- All five agreed, only differing in detail. The best dissent: raise everyone to $19 with
  30 days' notice and roll back if churn spikes. That tests the real base and protects
  the runway.
- Expansionist and executor disagreed on grandfathering: expansionist would raise
  grandfathered users later, executor would never touch the existing base.

WHAT WOULD CHANGE THIS DECISION: If $9 is below cost per user, give existing users 30 days'
notice of a raise. If new-signup revenue per visitor at $19 falls below the $9 baseline,
revert. Break-even is conversion at 47% of baseline ($9/$19).

NEXT 3 STEPS:
1. Pull subscriber count, monthly churn and cost per user — you'll know whether $9 loses
   money.
2. Put $19 on new signups only and compare 2 weeks against the prior 4 — it works if
   revenue per visitor is at or above baseline.
3. Survey existing users on what price they'd accept (a price-sensitivity survey) — this
   works if at least 60% say $19 or less is acceptable.
